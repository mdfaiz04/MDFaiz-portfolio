How each phase runs

One phase per session. I build it, then hand you the exit checklist. You verify against it — every criterion is something you can see or run yourself, not something you have to take my word for. Only once it passes do we open the next phase.

If a phase reveals something the plan got wrong, we amend the plan first and the code second. The plan stays the source of truth.

Standing rules — every phase, no exceptions

  • R1No facts in components. No name, date, email, URL, number, or sentence about you appears inside components/. It comes from content/ as props. Enforced by a pre-commit scan.
  • R2No raw colours or sizes. Every colour, space, radius, and font size is a design token. No hex codes, no arbitrary Tailwind values in class names. Enforced by lint.
  • R3No magic motion numbers. Every duration, delay, stagger, spring, and particle count comes from config/motion.ts. A bare number in a transition prop fails lint.
  • R4One reader of the environment. process.env is referenced in exactly one file, config/env.ts, and validated there. Enforced by lint.
  • R5Derived, never duplicated. If a value can be computed from content, it is computed — counts, durations, metadata, suggestions, the search index. Nothing is typed in twice.
  • R6Typed strictly. strict plus noUncheckedIndexedAccess. No any. Schemas infer the types, so data and types can never drift apart.
  • R7Nothing metered. No dependency that can generate a bill may enter the project. If a library needs an account, it does not go in.
  • R8Accessible by default. Keyboard reachable, visible focus, semantic landmarks, and a real static alternative under reduced motion — built in as we go, never retrofitted.

Code conventions

AreaConvention
FilesPascalCase.tsx for components, camelCase.ts for logic, kebab-case for routes.
ExportsNamed exports everywhere except Next.js route files, which require default. Makes every import greppable.
ComponentsServer Components by default. 'use client' only where interaction or canvas demands it, and pushed as deep in the tree as possible.
PropsExplicit interface per component, no prop spreading of unknown shapes. Content types come from the schema, never redeclared.
LogicPure functions in lib/, unit-testable without React. Components render; they do not compute.
CommentsOnly to record a constraint the code cannot express. Not to narrate what the next line does.
CommitsConventional commits, one phase task per commit, so the history reads as this plan.

Contract — config/env.ts

// The ONLY file in the project permitted to read process.env.
// Everything else imports the parsed, typed object.

import { z } from 'zod'

const schema = z.object({
  NEXT_PUBLIC_SITE_URL: z.string().url().default('http://localhost:3000'),
  NEXT_PUBLIC_ENABLE_BLOG: z.enum(['true','false']).default('false'),
  NEXT_PUBLIC_ENABLE_ANALYTICS: z.enum(['true','false']).default('false'),
})

const parsed = schema.safeParse(process.env)
if (!parsed.success) {
  // Fail loudly at build, never silently at runtime.
  throw new Error('Invalid environment:\n' + parsed.error.toString())
}

export const env = parsed.data

// Note: no secrets. There is no API key anywhere in this project.
// A fresh clone runs with zero configuration.

Contract — core schemas

// content/schema.ts — the contract. Types are inferred from these,
// so the data and the types can never drift apart.

export const LinkSchema = z.object({
  label: z.string().min(1),
  href:  z.string().url(),
  kind:  z.enum(['repo','live','doc','social','email']),
})

export const ExperienceSchema = z.object({
  id:         z.string().regex(/^[a-z0-9-]+$/),
  org:        z.string().min(1),
  role:       z.string().min(1),
  start:      z.string().regex(/^\d{4}-\d{2}$/),        // ISO year-month
  end:        z.string().regex(/^\d{4}-\d{2}$/).nullable(), // null = present
  summary:    z.string().min(1),
  highlights: z.array(z.string()).min(1),
  stack:      z.array(z.string()).default([]),
})

export const ProjectSchema = z.object({
  id:         z.string().regex(/^[a-z0-9-]+$/),
  name:       z.string().min(1),
  year:       z.number().int(),
  problem:    z.string().min(1),   // what needed solving
  approach:   z.string().min(1),   // what you built
  outcome:    z.string().min(1),   // what it achieved
  stack:      z.array(z.string()).min(1),
  highlights: z.array(z.string()).default([]),
  links:      z.array(LinkSchema).default([]),
  featured:   z.boolean().default(true),
})

export const SkillClusterSchema = z.object({
  id:       z.string(),
  title:    z.string(),
  blurb:    z.string(),
  items:    z.array(z.string()).min(1),
  evidence: z.array(z.string()).default([]),  // project ids — cross-checked below
  level:    z.number().min(0).max(100).optional(), // only if you choose bars
})

export const SectionSchema = z.object({
  id:       z.string(),
  navLabel: z.string(),
  order:    z.number().int(),
  stage:    z.enum(['attention','understanding','proof','interaction','connection']),
  enabled:  z.boolean().default(true),
})

// content/index.ts — catches broken references at BUILD time,
// not as a blank space on the live page.

const projectIds = new Set(projects.map(p => p.id))

Contract — derived statistics

// content/derived.ts — R5 in practice. Add a project, and the hero
// counters update themselves. They cannot drift out of sync.

export const stats = {
  projectCount:    projects.length,
  technologyCount: new Set(projects.flatMap(p => p.stack)).size,
  placementCount:  achievements.filter(a => a.kind === 'placement').length,
  experienceMonths: monthsSince(earliestStart(experience)),
}
One trap to avoid

experienceMonths depends on today’s date. Computing it in a Client Component causes a hydration mismatch, because the server and the browser can evaluate it at different moments. It is computed once in a Server Component and passed down as a plain number. Same rule for anything time-dependent.

Exit gate — Phase 1
  • npm test passes; all content validates.
  • Changing a skill cluster’s evidence to a non-existent project id fails the build with a message naming the bad id and listing valid ones.
  • Deleting a project makes stats.projectCount drop by one, with no other file edited.
  • Every fact matches your CV. You read the six content files and confirm them line by line — this is the moment to catch anything wrong.

Contract — canvas reads colour from tokens

// Canvas cannot use CSS variables directly. Rather than hard-coding
// colours (which would break R2 and the theme toggle), read the computed
// token values from the host element and re-read whenever the theme changes.

function readPalette(host: HTMLElement) {
  const s = getComputedStyle(host)
  return {
    point:  s.getPropertyValue('--brain-point').trim(),
    edge:   s.getPropertyValue('--brain-edge').trim(),
    pulse:  s.getPropertyValue('--brain-pulse').trim(),
  }
}

// Re-read on theme change so the brain recolours without a reload.
// No colour literal appears anywhere in the visuals directory.

Contract — the render loop must be interruptible

// Three independent reasons to stop drawing. All of them must work,
// or the canvas silently burns battery on a backgrounded tab.

if (prefersReducedMotion) { drawStaticFrame(); return }  // never animates
if (!isInViewport)        { pause() }                    // IntersectionObserver
if (document.hidden)      { pause() }                    // visibilitychange

05Portfolio
Assistant1.5 days

The zero-cost answer engine

A real retrieval system running entirely in the visitor’s browser. No API, no key, no server, no bill — and it cannot invent a fact, because every sentence is composed from validated content.

Tasks

5.1assistant/passages.ts — turn the content layer into ~35 retrievable passages: one per project, per role, per skill cluster, per achievement, plus profile and contact.
5.2assistant/tokenize.ts — lowercase, strip punctuation, remove stopwords, light suffix stemming, then expand through the vocabulary map.
5.3scripts/build-index.ts — build step producing a static BM25 index (~25 KB), written to lib/assistant/index.generated.json and committed.
5.4assistant/retrieve.ts — BM25 scoring with parameters from config, returning ranked hits with scores.
5.5assistant/intents.ts — ordered matchers: project-detail, skill-check, experience, education, achievements, availability, contact, overview.
5.6assistant/compose.ts — one composer per intent, each returning structured answer blocks built from content.
5.7assistant/suggest.ts — suggested questions generated from content, filtered by the section currently in view.
5.8assistant/fixtures.test.ts — ~40 question→expected-topic pairs including misspellings, unknown topics, and deliberate misses.
5.9sections/Assistant — the conversational UI: input, thinking dots, typewriter reveal, rich answer blocks, suggestion chips.
5.10Vocabulary tuning pass — run realistic questions, add the aliases that were missing. This is data editing, not coding.

Contract — the answer pipeline

// Every type here is structural. Answers are data, rendered by components.
// No composer ever returns a formatted HTML string.

type PassageKind =
  | 'profile' | 'experience' | 'project'
  | 'skill'   | 'achievement' | 'education' | 'contact'

type Passage = {
  id: string
  kind: PassageKind
  title: string
  text: string          // searchable body
  tags: string[]        // entities: technologies, org names
  sectionId: string     // where to jump on click
}

type AnswerBlock =
  | { type: 'text';     value: string }
  | { type: 'chips';    values: string[] }
  | { type: 'project';  id: string }
  | { type: 'timeline'; ids: string[] }
  | { type: 'link';     label: string; href: string }

type Answer = {
  blocks: AnswerBlock[]
  confidence: number    // drives the fallback path
  sources: string[]     // passage ids — provable grounding
}

type Intent = {
  id: string
  test: (query: NormalizedQuery) => boolean
  compose: (query: NormalizedQuery, hits: Hit[]) => Answer
}

Contract — answers are composed, never canned

// Every sentence is slot-filled from validated data. Change the CV,
// and the answer changes with it. There is no answers.json to maintain.

const composeProjectDetail = (project: Project): Answer => ({
  blocks: [
    { type: 'text',    value: `${project.name} — ${project.problem}` },
    { type: 'text',    value: project.approach },
    { type: 'chips',   values: project.stack },
    { type: 'text',    value: project.outcome },
    { type: 'project', id: project.id },
    ...project.links.map(l => ({ type: 'link' as const, ...l })),
  ],
  confidence: 1,
  sources: [`project:${project.id}`],
})

Contract — the honest fallback

// The single most important behaviour. When it does not know,
// it says so and offers something useful instead of guessing.

if (topScore < threshold && !matchedIntent) {
  return {
    blocks: [
      { type: 'text',  value: notFoundMessage(query.raw) },
      { type: 'chips', values: suggestTopics() },   // generated from content
    ],
    confidence: 0,
    sources: [],
  }
}
