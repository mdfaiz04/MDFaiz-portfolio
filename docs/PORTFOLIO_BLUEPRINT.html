02The
Contract

What “never hard code anything” means in practice

Taken literally the rule is unbuildable — some string has to exist somewhere. Taken usefully: every value has exactly one home, and that home is chosen by what makes the value change. With the paid API gone, the secrets layer disappears entirely — six layers, not seven.

LayerHoldsChanges whenEnforced by
L1 ContentYour facts — profile, experience, projects, skills, achievements, education, linksYour career changesZod schemas; import throws on invalid data
L2 TokensColour, type scale, spacing, radii, easing curves, animation durationsThe design changesTailwind v4 @theme; lint bans arbitrary hex in class names
L3 MotionEvery duration, delay, stagger, spring constant, particle count, rotation speedThe feel is tunedA single motion.ts config; no magic numbers inside components
L4 EnvironmentSite URL, feature flags, build modeThe deploy target changesOne env.ts that Zod-parses process.env; nothing else may read it
L5 StructureSection order, ids, nav labels, journey stageYou reorder the storyA single ordered sections registry that generates nav, scroll-spy and footer
L6 DerivedSEO metadata, OG image, sitemap, JSON-LD, stat counters, the assistant’s search index, its suggested questionsNever directly — computed from L1Pure functions and a build step; no hand-written duplicates
The distinction that matters

Your name and email belong in L1 content, not L4 environment. They are versioned facts about you, not deployment variables — they should live in git with a review trail. Environment is only for what genuinely differs between local, preview, and production. Putting identity in env vars is a common over-correction that makes the project harder to run, not more configurable.

L3 is new in this revision and earns its place: an animated site accumulates magic numbers faster than anything else. 0.6, 0.09, [0.16, 1, 0.3, 1] scattered across twenty components is exactly the hardcoding you asked me to avoid, and it makes the feel impossible to tune coherently.

The measurable test: grep the components directory for a quoted sentence, a date, a hex colour, a URL, or a bare duration. Zero hits. That check runs pre-commit, so the rule enforces itself rather than depending on discipline.

05The
Assistant

A real answer engine, for exactly zero rupees

You want an assistant that answers questions about your portfolio and costs nothing. Three ways to get there — I evaluated all of them.

ApproachReal costVerdict
Hosted LLM API (Claude, GPT, Gemini paid tiers)$8–40 / 1k questions rejected You’ve ruled out spending. Also needs a server, a key, rate limiting, and abuse monitoring.
Free-tier LLM API (Groq, Google AI Studio, OpenRouter free models)$0 today not default Free today. Still needs a key, a server route, and it can be throttled or withdrawn without notice. Kept as an optional flag, shipped off.
Browser-local LLM (WebLLM, transformers.js)$0 rejected 300 MB–1.5 GB model download on first visit. It would destroy your load time and be unusable on mid-range phones — actively damaging the thing it’s meant to impress.
In-browser retrieval & answer composition$0 — permanently chosen ~10 KB of code and a ~25 KB index. Answers in under 50 ms, works offline, cannot hallucinate, nothing to rate-limit because there is nothing to abuse.
Why this is the better answer, not just the cheaper one

Every portfolio chatbot on the internet is a thin wrapper around someone else’s API. An engineer reviewing your site knows that within two questions. A retrieval engine you built — tokeniser, inverted index, BM25 ranking, intent routing, answer composition, with a test suite proving it — is a substantially stronger signal, and it is the one thing on the page a reviewer cannot assume you outsourced.

It also removes the failure mode that would hurt you most: an LLM confidently inventing a job you never had, in front of a recruiter. This engine physically cannot — every sentence it emits is composed from data that passed Zod validation.

How it works

  1. Passages. At build time, the content layer becomes ~30–40 retrievable passages: one per project, per role, per skill cluster, per achievement, plus profile and contact. Each carries a kind, title, searchable text, entity tags, and a link back to its section.
  2. Index. A build script tokenises, lightly stems, and produces an inverted index with document lengths for BM25 scoring. Serialised to JSON, ~25 KB gzipped, shipped in the bundle. No network request at runtime.
  3. Query expansion. The question is normalised and expanded through vocabulary.ts — a content-layer alias map, so it’s editable data, not code. “tech stack” → technologies; “where do you work” → experience; “ML” → machine learning; “grad” → education.
  4. Intent routing. An ordered set of matchers classifies the question — project detail, skill check, experience, availability, education, achievements, contact, overview. Each intent owns a composer.
  5. Composition. The composer builds a rich answer from validated data: sentences with real slot-filled values, plus optional chips, a project card, a timeline fragment, or a jump link. Richer than a chatbot’s wall of text.
  6. Honest fallback. If the top BM25 score is below threshold and no intent matches, it says so plainly and offers three things it can answer — generated from your content, so the suggestions are never stale.

Making it feel like an assistant

The engineering above is invisible; the experience is what a visitor judges. Four cheap details do the work: a brief considered pause (~300 ms) with animated thinking dots; a typewriter reveal of the composed answer at ~18 ms per character, click-to-complete; answer blocks that animate in with a stagger; and suggested questions that shuffle to match whatever section you’re currently scrolled to. All of it is CSS and requestAnimationFrame — no cost, no latency.

Naming it honestly

The mockup labels this “AI Portfolio Assistant”. Retrieval and ranking are legitimately AI, so the label isn’t false — but do not add “powered by GPT/Claude” badges, because that would be. Recommended microcopy: “Ask anything about my work — answers come straight from my portfolio.” Accurate, inviting, and the precision itself reads as confidence.

Quality gate

The unusual advantage of a deterministic engine is that it is genuinely testable. fixtures.test.ts holds ~40 question→expected-topic pairs, including deliberate misses and misspellings, and runs in CI. If a content edit breaks retrieval, the build tells you — something no LLM-backed assistant can offer.

06Motion &
Design

The animated layer, specified properly

You want it to feel high-end and alive. The gap between “advanced” and “janky” is almost entirely discipline, so this is specified as a system rather than a list of effects.

The hero brain — the centrepiece

You asked for the brain to rotate slowly. The honest problem: the image you shared is a flat picture of a 3 D object, and CSS-rotating it looks broken rather than dimensional — the lighting and perspective stay fixed while the shape spins.

Recommendation: generate it instead. A Canvas 2 D neural point-cloud, tuned to resemble the reference:

  • ~220 points sampled across a brain-shaped volume (two lobes plus stem), deterministically seeded so it renders identically every load.
  • Rotation of ~0.0025 rad per frame around the vertical axis — one full turn in roughly 42 seconds. Slow enough to feel ambient, fast enough to read as alive.
  • Perspective projection with depth-driven size and opacity, so the far side genuinely recedes.
  • Synapse lines between near neighbours, opacity by depth, capped at ~350 edges.
  • A travelling signal pulse firing along a random edge roughly every 800 ms — the detail that makes it read as neural rather than decorative.
  • The reference’s glowing base platform, as an elliptical ring with a slow rotating gradient sweep.
  • ±6° damped parallax toward the cursor.

It is roughly 6 KB of code against a ~500 KB image, stays crisp on every display, recolours itself from your design tokens in both themes, and genuinely rotates. The fallback if you’d rather keep your image: composite it over a rotating ring and give it a slow float and depth parallax — convincing, and about an hour’s work instead of half a day. Decision 2 in §08.

Five layers of motion

LayerWhat it does
EntranceOne orchestrated page-load sequence: nav settles, headline rises word by word on a 60 ms stagger, brain fades up and starts turning, actions spring in last. Runs once.
Scroll narrativeEach section enters differently — the same fade-up five times is the tell of a generated site. Journey draws its timeline as you scroll; projects wipe in on a clip-path; skill clusters stagger; the contact wave amplifies on approach.
InteractionMagnetic buttons that lean toward the cursor; link underlines that draw rather than appear; project cards that lift with a light source tracking the pointer; a nav pill that slides between active sections.
AmbientThe brain; a slow gradient-mesh drift behind the hero; the signal wave in contact; a 2–3% grain overlay for depth. All paused by IntersectionObserver when off-screen.
TransitionNative View Transitions for theme switching and any route change — free, progressive, and smoother than a JS crossfade.

The discipline that keeps it smooth

  • Compositor only. Animate transform and opacity, never top, left, width, or height. This single rule is most of the difference between 60 fps and stutter.
  • Nothing animates off-screen. Every canvas and ambient loop is gated by IntersectionObserver and stops on tab blur.
  • Canvas budget. DPR capped at 2; particle count scales with viewport (~120 on mobile); glow drawn from a pre-rendered sprite rather than per-point shadowBlur, which is the usual cause of canvas frame drops.
  • Zero layout shift. Every animated element has its space reserved before it animates. Entrances must not move the page.
  • Reduced motion is a real alternative. One flag from L3 disables the lot — the brain renders a single static frame, reveals become instant, ambient loops never start. Not shortened durations: genuinely still, and genuinely complete.
  • Per-section imports. Motion code is dynamically imported so the initial route stays under budget.

Visual direction

Keep the reference’s instincts — deep ground, luminous accent, oversized type, real whitespace — while avoiding its one AI-tell: the violet-to-blue gradient is the single most over-produced palette in generated design, and a reviewer will have seen it fifty times this month. Proposal: a near-black ground with a faint cool bias, one luminous accent carrying every emphasis and interactive state, an editorial display face against a clean body face, and hairline rules doing the structural work that cards do in the mockup. I’ll present the palette and type pairing for your approval at the start of Phase 3, before any section is built.

Principal risks

  • Animation jank on mid-range phones — now the highest-impact risk. An ambitious hero that stutters is worse than a modest one that doesn’t. Mitigated by the Phase 3 exit criterion being measured on real hardware, and by the compositor-only rule.
  • Assistant brittleness. A deterministic engine handles unusual phrasings less gracefully than an LLM. Mitigated by the vocabulary alias map being content-layer data you can extend in seconds, and by a fallback that always offers something useful rather than failing.
  • Over-animation. Too much motion is the fastest route to a site reading as AI-generated. Mitigated by the five-layer budget in §06 being written down before we start, and by varying the choreography per section rather than repeating one reveal.
  • Generic palette. The reference’s violet gradient is the most common generated look there is. Mitigated by an explicit direction review in Phase 2, before any section is built.
